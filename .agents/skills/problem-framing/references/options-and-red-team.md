# Options And Red Team

只在高风险决策需要正式比较或反方评审时读取。普通需求使用 `SKILL.md` 的短格式即可。

## Decision Matrix

在三个方向中比较真正影响决策的维度，不为完整感填表。

| 方向 | 解决机制 | 复杂度归属 | 主要收益 | 主要代价 / 失败模式 | 所需证据 |
| --- | --- | --- | --- | --- | --- |
| 保守 | 保护现有行为的最小改变 |  |  |  |  |
| 平衡 | 收敛核心问题且控制范围 |  |  |  |  |
| 激进 | 更彻底的统一或重设计 |  |  |  |  |

三个方向必须：

- 解决同一个目标，而不是三个不同需求。
- 在范围、投入或风险偏好上存在实质差异。
- 说明复杂度由哪个模块、边界或流程承担。
- 证据不足时标为假设，不把不可执行方向用于凑数。

## Red-Team Pass

只挑战可能推翻推荐的关键假设：

- 是否混淆了名称相近但 owner、生命周期或 source of truth 不同的概念？
- 是否覆盖、重解释或静默改变用户内容、历史数据或 runtime behavior？
- 是否把复杂度扩散到调用方、兼容层、隐式约定或多个状态分支？
- 是否存在更成熟的数学关系、算法、数据结构或状态表达可以减少自定义规则？
- 推荐依赖的安全性、可逆性或收益能否被测试、preview、日志或接口证据证明？
- 是否夹带无关清理、未来路线图或尚未批准的架构变化？

发现足以改变方向的问题时，修订三个方向或停止并请求用户拍板；不要为了保住原推荐而辩护。
