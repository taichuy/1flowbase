# Frontend Interaction Architecture Gate

## Purpose And Entry

本 gate 是前端交互证据卡，用于核对已确认规则，或给 `problem-framing` 提供结构证据；不另起需求审批或固定回复模板。

命中导航、入口、详情容器、L0 / L1 / L2 / L3、同类对象行为差异，或用户提出“不顺手 / 不知道去哪 / 为什么有的不能点”时读取。最后一类属于产品诊断，交给 `problem-framing` 组织决策，不以局部样式修改替代。

## Interaction Evidence

先复用已确认需求、[workspace-rules.md](workspace-rules.md) 与当前页面证据，只补会改变实现的缺口：

- 首屏主任务与 L0 概览边界。
- L1 详情模型及适用对象：Shell 列表的 `Drawer`，Canvas 对象的 `Inspector`；inline 反馈不另算第三种详情模型。
- L2 完整管理与 L3 复杂执行的入口、到达路径和上下文保留。
- 同类对象的点击、下钻、反馈和返回 / 焦点恢复是否一致。
- 本轮所需 loading、empty、error、运行态与本地交互状态的来源。

只在关系不清或影响多个对象时补短 ASCII 图 / 一致性矩阵；不要求局部 bugfix 重画整页：

```text
入口 → 定位对象 → 查看详情 / 执行动作 → 当前上下文反馈 → 返回
```

图片或外部样本先区分信息层级、布局、组件组合与交互证据；参考图不能自行决定产品目标、状态语义或覆盖 `DESIGN.md`。仅拿到模糊图片时由 `problem-framing` 收敛，明确授权的视觉复刻范围按用户要求执行。

## Decision Boundary

- 已确认主路径、详情模型和反馈规则：实现既定结果，简述关键落点即可，不再输出另一份需求草案或请求同一确认。
- 未确认的页面边界、同类对象差异、新 L1 模型、状态语义或权限 / contract：把当前证据、冲突与最小待决事项交给 `problem-framing`；不在本 gate 批准新设计。
- 用户明确直接实现时，按其授权范围完成必要的交互判断；不能由此扩大权限、接口或非目标。
- 高频移动入口 / Tab / 状态栏是调查信号，不能自动扩大为规则重写；只有证据表明既定方案无法解释主路径时才升级决策。

## Exit

主路径、详情规则和反馈落点能由当前 contract 解释，且没有未决产品取舍时结束检查。行为变化交给 TDD，验收交给 QA；不形成“交互 gate → 需求模板 → 再做交互 gate”的循环。
