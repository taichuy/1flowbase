规则：用户要求修复动态／定时同步时，以整套模型集合及价格一致性为目标，修复原任务并实际执行验证；不要把任务缩为手工补某个新模型，或未经要求改成新增候选 PR 流程。
原因：单条补齐只能消除眼前症状，不能验证以后新增、更新和撤销是否持续同步；用户关心的是长期自动一致性。
适用场景：模型目录、价格目录及其他上游数据的动态或定时同步故障；缺少上游数据时明确记录不可用范围，不能以猜值凑齐。

补充规则：完整同步指最终覆盖范围完整，不等于单次请求或单个内存集合承载全量正文。用户明确要求参考现有 agent-flow 目录：浏览／查询按需分页，同步分批拉取、处理并保持一致性；不能先全量取回再截取当前页。

分页交互补充：先取得总数并显示总页数，再按当前页加载；翻页或刷新失败时保留上次成功结果、显示页与总数，并提示失败／重试，不能把网络错误渲染为目录为空或清空整张表。发布文件批大小与界面页大小应明确说明，不能只声称“已分页”而忽略实际下载批次过大。适用于远程目录查询与刷新体验。
