- 规则：agent-logs 找不到专属模型价格时，复用项目已有 `zero / any` 默认计费模型，费用为 0；不得另建“费用为空”作为该情况的产品语义。
- 原因：用户明确要求沿用已有默认计费能力，Root 先前参考 Langfuse 并绕开零价回退的提议增加了不必要的差异。
- 规则：第二层按轮次呈现系统提示词、用户输入和最终 AI 回复；工具、中间消息、子代理等在第三层轨迹查看，不默认把全过程摊在聊天视图。
- 原因：用户阅读聊天记录只需要每轮问题和最终结果，详情是已有采集事实的精简投影。
- 规则：Agent Logs 三层直接复用现有日志列表、对话详情浮窗、总轨迹/客户端请求交互，以及现有任务、对话和client_trajectory投影/正文存储；不新增采集专属三级UI，也不复制投影表族。
- 原因：用户暂停后连续提供现有列表/详情和总轨迹截图，明确第三层已经具备。需要调整的是纯采集事实进入现有结构的归属约束和读取依赖，不能把“数据接入”扩大成“重建日志产品”。
- 规则：Agent Logs 的 API 页面也直接复用 Agent Flow 的公共 API 文档工作区、工具栏和密钥弹窗；按应用类型由后端提供日志采集文档，前端消费真实 capability 字段，不另建静态 API 说明页。
- 原因：用户指出 `/applications/01a11699-d833-7373-b825-91d9916896b8/api` 不对，并明确要求参考复用 agent-flow 的 API 页面；统一入口和交互是本轮已授权修正目标。
- 规则：面向用户的 Agent Logs 采集器应为可下载安装的原生 Rust 客户端扩展，源码放在 `/home/taichuy/git/1flowbase-official-plugins/runtime-extensions/`；Shell / PowerShell 可负责一键安装，不以要求检出主仓库和运行 Node 开发脚本作为产品入口。
- 原因：用户提供采集器目录与安装详情原型，明确纠正当前 Node 采集命令，并要求官方下载交付。原生共享SDK与两阶段平台分发已获用户确认；本地日志采集与服务器保管分发包的执行位置需要区分。
- 适用场景：#2282 / #2300 agent-logs 方案、协议投影、UI、费用统计与后续验收；先前暂停已由用户明确“更新issue开工”撤销；实施与必要修复已授权。

- 规则：采集器采用两阶段分发：先从远程插件目录安装客户端分发包到 1flowbase，再由用户从当前 1flowbase 下载并安装原生 CLI；安装脚本、二进制和校验文件不能让用户终端直接依赖 GitHub 下载。
- 原因：用户再次提供“全部”目录原型，明确指出此前跳过了安装到平台的一层。目录“已安装”指 1flowbase 上真实存在的插件包，不指用户电脑已安装或 CLI 在线；前一轮禁止虚构客户端安装状态仍成立。
- 适用场景：Agent Logs 采集器目录、插件安装/版本/本地产物、下载分发、官方插件打包及安装器设计。原生客户端执行与共享 SDK 边界继续有效；服务器保管分发包不等于服务器运行采集器。

- 规则：采集CLI页顶部“全部”是采集器目录，具体采集器页签直接进入该包详情；目录下载按钮和页签应进入同一详情，返回回到“全部”。未安装平台包时先显示平台安装入口，不生成本地CLI命令。不得将已确认的详情页签悄悄改成来源筛选。
- 原因：用户指出“全部/Codex”切换无变化，复核其原型确认详情页签被误实现为source_client筛选；单一Codex目录下两者内容相同，违反已确认主路径。
- 适用场景：采集器目录、详情导航与其回归；按原型识别状态和页面转换，不能仅验证页签选中或按钮另行进入详情。

- 规则：按2026-10-08最新标注，采集详情移除“返回采集器目录”按钮，使用“全部”页签返回；准备Key改为仅当前详情内存保留的输入框及快速生成按钮。手动输入不自动保存/提交；生成调用现有应用Key接口并回填一次性token，复制命令通过现有安装器环境变量传入，下载URL与CLI参数不带Key，预览遮住值。
- 原因：用户明确标注三处UI/交互调整；这覆盖此前“仅终端输入、不在页面填写”和独立返回按钮的阶段选择。生成真实Key仍沿用服务端权限/生命周期，不能由前端造一个随机字符串冒充可用凭据。
- 适用场景：采集CLI凭据输入、快速生成、复制命令、页面导航与清理；不扩大为后端明文持久化、URL传密钥或修改原生发行包。
