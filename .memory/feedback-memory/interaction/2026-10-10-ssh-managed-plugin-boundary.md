---
title: SSH 插件按受管子进程与声明贡献定界
date: 2026-10-10 22
feedback_category: interaction
decision_policy: direct_reference
---

规则：用户明确 SSH 插件通过子进程和公开协议声明能力，由基座注册并执行治理；不能仅因需要数据表、设置页、接口和 MCP 注册就要求 HostExtension。角色与接口授权沿用现有体系。

原因：贡献内容与执行方式、宿主信任边界是不同维度。当前注册契约若只开放给 Host，应评估给受管插件开放声明入口，而不是迫使业务插件参与宿主内部实现。

适用：SSH 商业插件方案，以及类似声明 UI、数据、操作的受管业务插件。用户尚未批准具体底座改造方案；本记录不授权放开认证 factory、原生进程内执行或任意 SQL。

2026-10-10 23：用户批准清理误导选型的旧文档规则。已将选型统一到 `docs/architecture/plugin-composition.md`；保留源码分配限制为当前事实，未授权直接修改激活或注册实现。后续不要把文档修正当成底座功能已实现。

2026-10-11 11：用户纠正 SSH 正常配置流程应为新增、填写地址/账号/凭据、测试连通、保存，不应让用户常规执行探测与确认指纹等协议步骤。正常首次认证成功后由插件记录指纹；已有指纹变化仍走异常确认。适用于 SSH 插件交互，协议与生命周期工作继续由基座/SDK承担。

2026-10-12 17：用户再次纠正 Open 抽屉应为单个可输入的交互式 SSH 终端，而非 Command 输入框加 stdout/stderr 结果框。规则：xterm 渲染静态结果不算交互终端交付；验收必须覆盖持续输入、实时输出、Ctrl+C 和终端尺寸变化。原因：此前已要求普通终端，局部布局调整不能丢失该目标。适用：SSH Open 页面及后续通道实现；AI 连接复用与浏览器 PTY shell 分开定义，不擅自要求 AI 持有 shell 执行上下文。

2026-11-19 21：用户纠正 SSH 无法滚动的修复不应修改底座，应对照同宿主下可正常滚动的 compute-monitor 更新 SSH 插件代码。规则：插件局部 UI 缺陷先核对已有正常插件的容器与视口处理，不能因底座修改也能消除症状就判定应该修改底座；本轮授权仅为 SSH 插件修复。原因：同一宿主已有正常工作的对照，插件应按现有宿主契约自行管理布局。适用：SSH 滚动修复及同宿主仅部分插件异常的诊断；若确需底座变更，应另行给出证据并取得授权。
