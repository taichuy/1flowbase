# 用结构与数据选择控制备份体积

- 规则：以后台设置项的结构/数据选择作为范围边界。选中数据就完整导出该设置对应的数据，不再擅自排除执行日志、调用轨迹或其他持久化记录，也不追加一轮是否排除历史数据的确认。接口保持轻量。
- 原因：用户要自主选择大小；在数据模式内部再次裁剪内容会违背已选择数据的含义。
- 适用：后台设置备份目录、数据 inventory、体积优化和恢复方案。插件文件排除、文件实体独立可选仍沿用已确认边界；必要插件身份/引用记录已获授权携带。

- 2026-09-22 09 用户进一步纠正：结构与数据不是独立勾选；每项三选一，名称固定为「不备份 / 结构 / 结构和数据」，默认不备份。「结构和数据」必须包含该项配置，UI管理必须同时包含页面路由、菜单、布局和代码。原因是数据模式应是完整备份，而非排除配置的仅记录备份。

- 2026-09-22 14 用户纠正模板入口：删除备份页独立的“大块可移植结构模板”面板，模板导入统一进入现有「导入备份」，模板导出收进「创建备份」。原因是独立面板挤占列表、增加重复入口；适用于本项目备份/模板页面，功能差异放在操作弹窗中，不另铺常驻说明面板。
