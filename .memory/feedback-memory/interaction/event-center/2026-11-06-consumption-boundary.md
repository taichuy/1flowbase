# 规则

- 本次事件中心中，订阅、诞生、消费是触发时机。消费 = 消息从队列取出、责任交给消费者；之后的成功、失败和取消归消费者，不决定是否已消费。
- 用户最后的直接纠正覆盖此前问答中“每个消费者成功完成后触发”的选择，后续不能恢复旧解释。
- 用户选择事件本体与观察日志均不持久化，进程重启允许丢失；不能据可靠性偏好擅自加入 Outbox、恢复账本或副作用治理。
- 通信链路已明确为微信等入站指令 → 发布事件 → 工作流；通知由工作流动作发送。

# 原因

AI 将队列交接与业务成功混为一谈，进而把原本的瞬时事件需求扩大为可靠工作流恢复系统。用户要求职责单一、做深而不做大。

# 适用场景

适用于本次事件中心、事件工作流和通信指令绑定的设计与后续实现。此定义不改变既有可靠通知 Outbox 的 ACK 契约，也不自动取消消费者自己的业务记录。用户已于 2026-11-06 确认方案并授权本地实现，追加后台列表复用共享表格组件；没有指定截止日期。
