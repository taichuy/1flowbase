# 规则

- 用户要求后台共享表格时，应参照/settings/applications的整体组合：DataTableLayout、DataTable工具栏、列设置与完整分页区（总条数、页码、每页条数选择），不能只引入底层DataTable就宣称已对齐。
- 不给设置页额外添加单独大标题卡片；此轮事件中心的标题面板明确要求移除。
- 不同tab用不同URL表示，直接打开、刷新、前进/后退均从URL恢复选择。
- 共享表格行操作默认直接显示前两个按钮，从第三个起收纳进“更多”；所有操作和“更多”均通过普通单击触发，避免唯一的查看操作仍需先展开菜单。

- 事件行操作采用简短文案“详情”，不用“查看详情”（用户明确纠正）。

- 事件详情的 JSON 字段直接由共享高亮区块展示原值，包括 `null`；不把空值或布尔值换成业务解释提示，也不补造 `{}`。

- 事件中心必须贯通系统既有事件总线的定义/注册、真实订阅与消费观察；仅在目录列系统条目、运行视图却只覆盖新接入事件，不算完成原始需求。系统来源可只读，但不能以只读代替运行接入。

- 2026-11-07 用户确认事件目录用“事件标识”（contract_id）和“来源分类”；单次event_id称“事件实例标识”。随后确认删除契约版本、注册状态（曾改名事件状态）和观察覆盖管理列，生命周期继续称可用触发时机。接口字段沿用后端DTO，不另造展示alias。
- 2026-11-07 用户已批准整体简化：事件标识在所属作用域内唯一对应当前Schema；不做事件版本/历史工作流兼容平台，允许清理此次新功能残留。只有自定义事件允许启停；2026-11-07 用户进一步纠正，目录与详情的启用状态统一用开关展示，自定义事件按 enabled 显示且有更新权限才可操作，系统/插件显示为开启且禁用（替代此前的—展示，DTO 的 null 仍保持不变）；所属模块/发布点在详情，纯声明模板不重复列为普通事件。原始业务队列数据和既有投递语义不在残留清理范围。

- 2026-11-08～09 用户要求运行视图“做得更深，而不是更大”：先按真实任务审计和分层，不堆说明/技术ID/诊断字段。核心列表和判断信息优先首屏；技术身份和预算按需，观察不完整、失败和过期必须可见。来源—队列有明确选中与主从，动态按时间/事件/阶段/准入优先，完整上下文走同一详情模型。小屏优先复用共享记录能力；筛选明确限于已获取快照。真实截图和完整交互取证不能由源码或测试绿灯替代。适用于事件运行视图及类似B端观察控制台；不授权扩展业务数据/图表/后端功能。

- 2026-11-09 用户明确：打开事件运行页就应持续观察更新，不能只获取一次快照、等过期后要求用户手动刷新；只有本地计时、没有重新获取后端数据，不算持续观察。适用于当前队列与近期动态；具体传输方式沿用已有能力，不据此扩展事件业务语义。

- 2026-11-09 用户要求从事件运行页主视图移除自动更新周期、快照时间、宿主只读说明、观察损失计数窗口说明和订阅队列概述；持续更新应由系统执行，首屏保留业务列表与操作，不常驻这些解释性文字。诊断信息按需放观察详情，实际异常提示与普通说明分开处理。

- 2026-11-09 用户明确事件运行页工具栏布局：搜索框靠左，刷新、观察详情与列设置放搜索同一行右侧，不再为按钮独占一行。适用于运行页的队列与动态列表；目的是压缩无效纵向留白并集中列表操作。

- 2026-11-09 用户否定队列顶部“待处理投递 Top 5”图表。此前按参考图解释为观察资源统计的方向已被同日后续纠正覆盖：用户要看真实队列统计，不能使用监控缓存占用替代队列大小。参考图只提供布局参考，不授权虚构历史或缺失统计。

- 2026-11-09 用户确认直接实现事件运行页三层布局：第一行动态指标，第二行 ECharts 图表，第三行搜索工具栏与表格。指标与图表的内容以后续“真实队列统计”的用户纠正为准，此前观察占用方案已废止。趋势仅从本次打开后的真实队列快照采样，不虚构历史、不把统计不可用当零。先展示效果，用户确认后再执行测试。

- 2026-11-09 用户再次明确纠正：当前队列页要看队列本身的数量、排队与领取/消费情况，观察记录和监控元数据的空间没有用户所需价值。不能仅把“观察占用”改名后继续使用同一数据；队列字节大小若契约未提供，应说明缺口，不用监控数据大小或宿主总线全局字节数代替当前队列的大小。当前三层布局保留。

- 2026-11-09 用户进一步确认入口归属：活动记录的大小、保留、过期/淘汰等统计应放在“近期动态”里，以指标与图表呈现；当前队列只展示队列本身的投递/消费统计。后续用户进一步明确：原始诊断清单应被前两行可理解的报表替换，不保留“更多 → 记录诊断”入口；该旧菜单方案已废止。

- 2026-11-09 用户强烈纠正：“把看不懂的详情换成报表”意味着直接将保留时长、容量/预算、过期、空间清理、超大丢弃、投递拒绝和分范围统计转换为近期动态第一行指标、第二行图表，移除旧诊断入口及原始字段抽屉；不能只加部分图表后把原始清单藏进更多菜单。分钟与 KiB/MiB 直观展示，部分范围缺统计须在对应图表中明示，已有范围的真实计数不能因此整体变成未知。主机实例/UUID 等技术标识不作为普通用户报表主体。

- 2026-11-09 用户统一事件触发时机的展示名称为“发布、消费、订阅”，删除“诞生”和“时”后缀；事件中心及工作流配置/详情保持一致。原因是“诞生时”不直观，短名称更易懂。适用于事件触发阶段名称；后端既有 `published / consumed / subscribed` 语义和协议值已匹配，沿用这些标识。

- 2026-11-09 用户要求“近期动态”和“当前队列”的指标、报表与表格使用同一页面纵向滚动，表格按当前页内容自然展开、分页随内容放到底部；不保留表格内部纵向滚动。原因是嵌套滚动影响连续浏览，适用于事件运行页主视图；先预览效果，确认后测试；用户随后认可此方向并授权验证。

# 原因

用户在事件运行页停留后只看到快照过期黄条，明确要求页面打开期间能够持续观察；手动刷新式静态快照不满足该用途。

用户明确要求 JSON 字段原样展示；将 `null` 替换为“未声明结构”提示造成预期偏差。

用户进一步指出原运行视图把必要复杂度直接推给用户，主要判断和操作被技术信息遮挡；需要减少理解、判断与操作成本，不能用减少代码行数或新增组件数量代替体验结果。

此前事件页把按钮放在表格外，并加了占据大块空白的标题面板；tab只用React本地状态，既不符合参照页面也不能分享/恢复视图。

# 适用场景

事件中心和后续后台表格页面调整。数据契约、权限和事件业务语义仍以后端为准；此反馈不授权额外新增业务筛选或后台改造。
