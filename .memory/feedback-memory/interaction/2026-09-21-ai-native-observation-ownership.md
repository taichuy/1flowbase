# AI Native Observation Ownership

- 规则：AI Gateway 日志设计保持“映射协议层 → AI Native → 供应商”的职责边界；供应商协议作为记录真值不等于供应商插件拥有日志系统。优先核对 AI Native 与供应商之间出入站边界的旁路观测，集中承担关联、轨迹投影和持久化责任，避免各供应商分别实现通用日志机制。
- 原因：用户检查 #2104 实现后指出，直接在各供应商层承担记录复杂度不合理，要求先重新核对技术方案。
- 适用场景：LLM 轨迹、协议记录、供应商插件采集与 AI Native 边界设计。必须区分逻辑 owner 与当前物理采集位置；上移采集前验证是否能观察最终协议，不能将标准输入冒充供应商实际报文。
- 确认：2026-09-21 用户确认平衡方向并要求更新 Issue；已更新 #2104 与 #2107。共享 SDK / 统一接口收敛薄采集，独立有界旁路负责日志处理，原始协议证据与语义轨迹分开；D1/D2 保留，旧 P3/P4/P5 需重新固定替代 Work Packet。具体缓冲/溢出策略在 Packet 中固定；本次仅更新 Issue，未修改产品代码。

- 最新澄清（2026-09-21）：用户期望插件只负责上游连接与通讯，日志监听 AI Native 翻译为供应商协议的出入站边界，不应要求供应商插件接入日志 SDK。共享 SDK 只减少重复，不能视为满足该职责分层。核对现有 ProviderInvocationInput 与插件协议构造事实，区分目标架构和现存实现；不得以最终网络帧采集需求替代用户要求，也不自动扩大为全量传输重构。此前“薄采集点”方向需按此澄清重新评估。

- 后续校正（2026-09-21）：用户回忆并确认AI Native实际是统一出口，供应商插件负责将Native翻译后发往上游；此前“插件只做传输”不是当前架构事实。正在比较以Native契约为主的统一轨迹与可选供应商原始证据，尚未批准新实现。不要为日志任务擅自迁移现有插件翻译职责，也不要把Native快照标成原始上游报文。

- 已确认修正（2026-09-21）：用户批准“Native主轨迹 + 供应商扩展信息 + 可选原始证据”。保留插件翻译与通讯职责，原始协议不再驱动主语义轨迹；语义/原始完整性独立，Native内容不冒充供应商报文；来源及关联范围明确，原始附件按需加载。#2104/#2107重新进入实施/QA。

- UI 纠正（2026-09-21）：用户明确只要求增加轨迹入口，不能借此隐藏原对话、详情输入/输出、节点输入/处理/输出或追踪中的工作流节点关系。总轨迹icon放元数据，局部轨迹icon仅LLM节点；追踪树仍呈现节点关系。轨迹视觉以用户DeepSeek harness截图及本地源码为参照（三泳道时间轴、紧凑事件行、选择后展开），避免编号按钮加JSON墙替代参考。原因：此前overview存在时隐藏payload、把子节点移进轨迹弹窗都越界。适用于本任务日志UI及后续增量入口改动。

- 补充纠正（2026-09-22）：日志运行详情原有底部 UI-only 对话输入框也属于应保留的 UI；纯记录语义不构成隐藏该输入框的授权。用户要求恢复原界面时沿用原 composerUiOnly 行为，不擅自增加模型请求或删减控件。

- 最新确认（2026-09-22，覆盖上一条输入框要求）：用户明确选择不要输入框，只在运行详情底部显示记录中的模型和推理强度，样式参考 AI 助手的模型名及灰色推理强度；这是历史配置只读展示，不是可编辑的运行偏好。

- 轨迹交互纠正（2026-09-22）：DeepSeek harness 的选中步骤是左侧列表、右侧独立检查器，不是行内折叠展开。严格复刻需核对 TrajectoryTable.tsx/module.css 的左右独立滚动、关闭、宽度调整与移动端右侧覆盖；不能只复刻时间轴颜色而替换关键布局。此前“选择后展开”应解释为打开右栏。

- 数据真值纠正（2026-09-22）：用户明确面向用户的轨迹以客户端映射协议的实际请求与返回为主，不以 AI Native 为默认内容，更不是供应商原始协议。Native 若有诊断必要可单独标注展示。DeepSeek 复刻包括按轮次/调用/消息类别归纳，以及概述、参数、结果、Schema、计时等按记录类型组织的详情，不是左右布局加 JSON。原始客户端记录不得从 Native 反推伪造；缺失历史数据应明确未记录。

- 等待占位纠正（2026-09-22）：用户指出运行等待时原有助手侧默认占位应支持随时打开对应日志/通道及回复查看。核对a08ca1f3cb确实删除了fallbackConversationAnswerContent，1eed3926f仅把日志按钮补到用户气泡。运行状态占位与伪造模型回答应区分；纯记录要求不能作为删除状态反馈及原入口的理由。恢复方案应依后端状态显示，并在真实回复出现后替换占位、不重复记录。

- 已确认职责（2026-09-22）：用户批准保留 Native 必要执行证据，并区分翻译/执行与日志存储责任。日志设施拥有持久化与查询；原始客户端协议不能重建内部实际执行，Native 输入只证明交给插件的内容。先做同调用内精简和可靠引用，保留独有事实，不删除 Native、不引入跨会话通用去重或修改插件。

- 最新方案确认（2026-09-22）：用户确认两套职责不同的日志：客户端请求保留原始协议，工作流内部事件记录LLM实际系统输入、预热/生成/续接、调用与尝试。AI Native不再作为面向用户的日志名称。精确关联本次触发请求与历史上下文来源并支持双向定位；不得按时间或空输出推断来源/预热。沿用同调用正文引用，Resume时间线不动。本次仅要求更新线上#2104方案，新增AC-027–032待实施，不将既有交付等同新增方案已完成。
