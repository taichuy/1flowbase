# Rule

当用户将性能任务限定为本地前端区块渲染时，以本地后端搭配当前前端或静态预览取证；公网 URL 仅用于定位对应页面。分别报告源码读取、编译、挂载和区块业务 API 等待，不把业务数据完成时间混成编译耗时，也不为了 500ms 渲染目标自行扩大到后端或业务响应缓存。

明确区分调试“刷新区块”与浏览器刷新 / 再次打开：前者重新读取、编译、求值和重建实例，绕过已有计算结果；后者可复用完整身份匹配的产物。常驻编译 Worker 只复用基础设施，不跳过本次编译、不保留组件状态。之前把调试刷新改为产物复用的临时实验不符合这一边界，不再用它证明最新候选的性能。

缓存优化优先采用成熟内容寻址、两级缓存、哈希表加双向链表 LRU、IndexedDB 元数据索引与有界维护队列；用户明确要求成熟架构、数学表达与既有算法 / 数据结构，不以任意延时、扩大容量或临时规则堆叠代替。

# Reason

用户指出公网穿透增加了网络链路，不适合此次定位；随后明确此次只做前端区块渲染优化，后端接口先不用管。

用户纠正“刷新绕过缓存是待消除重复工作”的表述：调试刷新从零执行是合理产品语义，页面刷新才应复用；并要求为 LRU 全量扫描增长风险提供成熟方案。

# Applies When

后续继续此区块渲染优化，或用户明确设定相同本地 / 前端性能边界的任务。源码真值仍来自后端；该规则不表示后端耗时已被排除为其它任务的原因。
