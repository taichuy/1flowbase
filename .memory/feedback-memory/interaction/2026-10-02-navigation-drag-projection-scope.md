## 规则

讨论导航拖拽投影时，同时考虑顶部栏目排序和左侧分组、页面树的排序及归属预览；不因截图标记位于顶部而省略左侧分组。跨顶部与左侧移动仍需单独明确产品边界。

## 原因

用户指出“只是导航栏分组吗？左侧分组呢？”，目标包含左侧树中拖拽后的落位与层级可预测性。

## 适用场景

Frontstage 导航拖拽交互方案、范围界定与后续实现。

## 投影视觉纠正

用户于 2026-10-02 否定无样式留白和重叠的去向文字。导航拖拽投影应采用空白、半透明蓝色选中块，与现有设计模式选中态协调；去向可通过辅助阅读保留。适用于顶部排序、左侧同级排序与移入分组预览，避免文字徽标叠加原菜单和拖拽影像。

## 投影与实际落位一致

用户反馈“都有投影了，为什么拖了没有效果”。合法落点显示投影后，在投影区域松手应提交相同目的位置，并能从后端重新读取到该顺序；验证必须覆盖拖到末尾、已有相同排序值与刷新后的保存结果，不能仅凭投影截图确认拖拽完成。适用于导航拖拽预览与持久化验收。

## 移动弹窗的层级与投影

用户于 2026-10-09 指出移动弹窗默认展开整树不合理，要求按顶部菜单及分组逐层展示，每次展开只呈现直接子节点。弹窗应支持拖拽；点击目标分组时也应自动在该分组下放置移动投影。

原因：用户需要直观看见移动后的归属与落位，单纯高亮目标分组不足以表达结果。适用于 Frontstage 页面移动弹窗；沿用蓝色半透明投影，预览、拖拽落点和最终保存位置必须一致。

## 页面点选与整组移动

用户于 2026-10-09 进一步纠正：弹窗点选页面时，应将移动投影放到该页面后面；顶部菜单栏和左侧分组本身也必须具备移动能力，移动分组时整个子树一起移动。

用户同日确认整组跨层级移动：顶部菜单分组移入另一个分组后成为目标下的子分组，原独立菜单入口消失，组内页面 URL 随新归属变化；页面内容和 ID 保留。

原因：页面也是明确的位置锚点，移动能力应覆盖导航中的页面和分组，不能只让分组成为目标而无法移动分组本身。适用于导航设计模式移动入口与弹窗落位；涉及顶部路由入口跨层级变化时需核对已确认路由语义。

## 弹窗投影占位与根层命名

用户于 2026-10-09 用截图指出页面之后的蓝色投影贴在节点边缘并与相邻行重叠，同时质疑包含顶部菜单的根容器为什么叫“不分组”。当前位置正确并不足以通过视觉验收：投影必须清楚表达移动后的空间位置，不能遮盖现有节点。根层是没有父节点的导航层级，不是真实分组；命名须表达根层含义，避免把顶部菜单也描述为“不分组”。

- 2026-10-09 20：移动弹窗的人工根容器显示为“顶部导航栏”（用户指定）；名称需表达顶层导航位置，避免“不分组”造成误解。适用于移动目标树，投影必须独立占行而非覆盖节点边缘。
