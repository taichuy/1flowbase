- 规则：当用户已经点击 GitHub 等一键认证入口，直接发起该入口的认证动作；不再进入只有同一个登录按钮的中间页。需要输入的认证方式保留表单。
- 原因：用户指出当前选择 GitHub 后还需再次点击使用 GitHub 登录，增加了没有新增信息的操作。
- 适用场景：登录方式选择器、一键授权入口与其插件激活行为设计。用户已确认使用声明式入口动作（显示表单 / 发起外部认证）；本轮不开放任意点击脚本。

- 账号语义：GitHub 首次注册创建独立普通账号；已有用户先登录，再主动绑定 GitHub，不按邮箱自动合并。用户明确确认这一方式。首次资料按供应商可验证信息初始化，公开昵称不冒充实名，后续授权不覆盖本地编辑。

- 2026-10-21 补充：GitHub 等一键认证在点击后等待跳转时复用通用 LoadingState（thinking），不加“正在跳转”等额外文案。原因：外部登录等待较久，用户需要即时统一的加载反馈。适用：声明为 external_login 的认证入口；失败和浏览器返回仍恢复可操作入口。

- 2026-10-22 纠正加载交互：一键认证等待时使用半透明蒙层叠加通用 Thinking，原按钮、表单和操作上下文保留可见；只禁用交互，不直接替换整个内容区域。原因：用户否定“整个区域变成加载界面”，要求能够看到之前操作了什么。适用：一键登录的待跳转加载态；不增加额外文案。此规则取代上一轮隐藏入口区域的实现。
