topic: 网关排障以用户指定的真实客户端为入口
summary: 客户端起点的问题先用对应真实客户端复现，HTTP脚本只补充取证。
created_at: "2026-11-13 11"
updated_at: "2026-11-13 20"
decision_policy: direct_reference
---

- 规则：用户明确问题起点是 Claude Code 等客户端时，以该真实客户端和可隔离会话做端到端复现；脚本可记录协议和补充受控对照，不能替代客户端兼容结论。
- 原因：用户纠正仅做协议脚本测试的做法；实际客户端还涉及扩展字段、自动降级、重试、会话续接和本地用量统计。
- 适用：从具体 AI 客户端发起的网关兼容性与稳定性排障。此偏好不要求所有接口事实查询都启动客户端。

- 已排除的上游异常：用户明确说明429等上游异常不用处理时，不再反复探针或把真实上游成功作为网关修复交付阻碍；继续用真实客户端+可控上游验证网关内部协议、续接、恢复与状态，完成后直接报告。原因是已知上游故障不应挤占修复本项目缺陷的时间；仅适用于用户已明确划定排除边界的该类排障。
