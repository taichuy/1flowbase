- 规则：安全设置默认提供账号密码 Tab；认证插件声明的认证方式分别生成 Tab，例如 GitHub。GitHub 插件展示名称使用 GitHub，不附加“一键登录”。绑定页面必须显示实际绑定的供应商账号，不能只显示无状态的绑定按钮。
- 原因：用户确认首次注册资料已正确获取，但指出密码表单下附加“外部账号绑定”区块不符合认证方式管理结构，也无法辨认已经绑定的 GitHub 用户。
- 适用场景：个人安全设置、认证插件的账号管理声明与绑定状态查询。
- 已确认边界：用户批准平衡方案。解绑保留原账号的不可变身份归属；匿名再次授权不建新号、不静默恢复。原账号验证供应商身份后才能恢复；保护最后一种实际可用登录方式。冲突支持切换账号和取消，完整迁移是独立高级流程，不自动合并账号、角色或资源。

- 2026-10-20 补充规则：账号密码是内置认证基座，个人安全设置只保留旧密码、新密码、确认新密码表单；GitHub 等插件的认证与绑定放在各自 Tab 内，不以前置 GitHub 验证串联本地密码表单。
- 补充原因：用户明确否定“通过 GitHub 验证身份后才出现首次密码表单”的设计，认为混淆内置密码与插件认证边界；本轮暂不扩展 GitHub-only 账号的自助首次设密。

- 2026-10-20 补充规则：个人资料面向普通用户只展示其角色，不逐项展示内部系统权限代码。原因：权限标识属于管理与实现细节，不应占据用户个人信息页。适用：个人资料与普通用户账号查看页面；实际授权仍以后端为准。

- 2026-10-20 再次纠正：角色必须在个人资料详情区有明确“角色”字段，不能仅保留头像旁的 member 徽标。原因：用户要求查看自身角色，纯徽标不满足字段可发现性。适用：个人信息详情。
- 2026-10-20 姓名初始化边界：GitHub 首次注册由 GitHub 插件显式提供 name=GitHub 用户名；宿主仅校验并保存显式姓名，不做“空姓名取账号”的通用默认，不在资料页补值，不回填旧账号或覆盖已有姓名。原因：用户明确要求默认行为归插件所有。适用：GitHub 注册与外部认证资料映射。
