# 区分协议前序请求与用户对话轮次

- 规则：看到 `previous_response_id` 时先查它指向的请求种类，不直接称为“上一轮用户对话”。
- 原因：用户指出新开会话也出现该字段；本次数据库证实前序请求为 `request_kind=prewarm`、`generate=false`、无用户 prompt 或 turn_id。
- 适用场景：解释会话续接、预热、恢复与模型日志关联时，区分后台协议请求与用户可见对话。

## 2026-10-10 二级投影边界澄清

- 规则：打开选定已完成任务的二级对话投影，末条应为该任务的最终生成消息；之后的 prewarm 不应作为对话轮次追加。保留预热协议事实与真实会话关联，不等于将它投影成业务消息。
- 原因：用户指出最终回复后追加系统提示词，并质疑预热记录的历史滚动。已有会话归属和用户轮次身份必须分开核查，不得从 turn_id 缺失推断会话归属缺失。
- 适用场景：二级投影锚点、协议预热分类、会话历史分页及日志入口诊断。滚动故障需实测分页，不得仅凭身份字段猜测。
