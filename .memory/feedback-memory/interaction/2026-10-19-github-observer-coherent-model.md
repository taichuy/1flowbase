- 用户在周/月排名历史交付后明确指出日榜、周榜、月榜、社区和定时任务整体混乱、不合理。
- 规则：在本观察系统继续增加入口、表或自动化前，先明确榜单来源、排名指标、历史比较口径和更新依赖，收敛成完整用户流程；局部功能验收通过不等于整体产品设计合理。
- 原因：日榜采集官方Daily，周/月却从每日收录频次派生；同频项目使用内部ID确定名次；06:00采集和06:15统计独立触发。来源、时间维度、存储与内容输出在同级导航中混列。
- 适用：本任务 GitHub 观察库及后续结构调整。用户随后明确选择“按每日收录统计的周/月观察榜”，因此不得改为官方Weekly/Monthly Trending。用户已经确认导航收拢、收录天数并列和采集成功后串行统计的方案，授权停用旧06:15独立统计计划；旧数据、个人备注、报告及历史快照保留。
- 已按该方向整理为项目发现、观察统计、项目库、报告；管理与旧入口单独归档。手机验收不能只检查首屏宽度：本轮最后一条可达测试识别了内容自然高度超出区块分配、导致不可滚动到达的问题；已通过直接消费宿主available.height并设置内部滚动修正。
