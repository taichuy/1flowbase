---
title: 日志优化限定详情与运行时，保持统计和对话纯记录
date: 2026-09-28 19
feedback_category: interaction
decision_policy: direct_reference
---

规则：用户要求 Gateway 日志去重优化时，任务统计与对话保持现有精简纯文本记录模式，不增加关联、统计、聚合或正文引用；当前范围只覆盖日志详情与运行时写入。不把“增量投影”泛化为所有日志层的架构重构。

原因：统计和对话已经是精简后的日志投影，额外关联和聚合增加复杂度，偏离本次减少底层详情膨胀的目标。用户明确纠正了前一轮将 node/message 和统计一并重构的建议。

适用场景：本次 Gateway 存储/详情方案、Work Packet 和后续实施验收。保留原工作流/API/客户端轨迹/执行顺序；统计与对话仅验证原功能不被上游改造破坏，不作为优化对象。

2026-09-28 19补充纠正：用户否定“保留全部逐片永久事件，仅正文复用/分段压缩”作为最终架构，要求改变长期记录粒度，尽量一任务一条/几条。后续先区分实时变化通知与真实持久化对象/事实，按真实item归并delta，避免每token创建Message/Reasoning和长期事件，再采用任务归档与生命周期收敛。不能只将相同事件换容器后称为完成重新设计。

原因：每次流式更新附带的关系行、对象与索引成本会超过正文，短期过程被永久化导致持续增长。ephemeral用于可重建短期高频状态及发布编排约5m缓存；不能将恢复真值、长期上下文或完整历史日志搬进cache来宣称节省。

适用场景：本次重新设计与后续实现。任务少量长期详情行不等于删除必要执行/账务/Outbox状态；客户端raw与独有来源证据仍完整保留在归档内部。新目标的收益需要重新测量，旧47.3%/57.1%不得作为新方案保证。
