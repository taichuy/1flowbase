- 规则：本地后端一次性命令执行接口向调用方只要求一个命令字符串，不拆为 program / args，不把底层进程启动细节转成调用方负担。
- 原因：用户明确纠正先前方案，认为执行命令一个字符串即可，其他输入多余；超时、输出读取和进程回收应由后端内部承担。
- 适用场景：当前本地一次性命令通道的接口设计；不据此推导其他程序执行 API 都必须使用 shell，也不视为已批准整体方案或实现。
- 2026-10-30 11 用户继续纠正：本接口应作为“其他权限”中可勾选的普通接口，有接口权限就可执行；不得再增加独立的 root-only 资格判断或要求填写环境变量才能启用。原因是既有角色授权已经承担是否允许调用的职责，额外门槛增加了不必要的使用成本。
- 删除部署配置不等于允许悄悄换成硬编码超时或输出上限；仍遵循用户禁止猜测业务容量的原则。Windows 原生命令执行需要纳入修订方案，不能把 Unix 实现兼容冒充三平台已验证。
