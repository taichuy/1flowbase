# Frontstage 代码哈希渲染身份规则

## 规则

- 持久化源码是区块程序真值；同一实例的源码内容哈希未变化时，页面、路由或 Tab 切出切回只恢复已有渲染产物，不重新创建 Worker、编译源码或执行 `main`。
- 导航不是刷新或重新验证信号。需要响应 Page/Tab Signal、接口结果或其他运行输入时，必须由源码中的显式注册机制驱动；不能用组件 remount 兜底。
- 接口连接器、变量注册和其他关联能力只生成或注入可见源码，不建立与源码并行的隐藏 binding 状态。
- 安全会话、运行时 ABI 变化和显式重试属于缓存命名空间或控制面失效，不把它们伪装成源码变化。

## 原因

所有能影响区块能力和关联关系的内容都应在源码中可见；代码未变化时由路由生命周期触发冷执行，会重复加载 Worker 模块、编译和执行，并让页面切换错误地承担刷新语义。

## 2026-10-04 11 用户补充

- `/demo/*` 连续打开大量 Ant Design 页面属于极端压力样本；正常 `/route` 小页面的编译后保留、切回接近原生的体验是需要保护的目标。
- 用户曾授权 Issue #2251 试修 30 分钟失活保留，随后明确暂停实现；固定 30 分钟主策略已被下述新反馈取代。这不是将后端 ephemeral 缓存统一调整为 30 分钟。
- 排查时区分编译产物命中、React 实例保留、源码/权限校验等待与真正卸载后的重建；不能把“看起来刷新”直接等同于重新编译。
- 优化应先解决资源所有权、隐藏期间活动与淘汰后的引用释放，不以频繁重建正常页面来消除压力样本的内存增长。权限/会话失效与页面删除仍是立即释放边界。

## 2026-10-04 12 用户修正：热度与资源预算

- 规则：不再以固定 30 分钟作为主要淘汰依据。重复打开的页面应提高保留优先级，一次性访问的页面优先回收；访问热度需能老化，不能使用永久累加计数锁住历史热点。
- 规则：当前页面属于活动工作集，不建立第二份缓存；后台保留实例可受客户端资源预算约束。用户提出 1GB 或浏览器上限作为讨论示例，尚未批准对所有客户端统一设置 1GB。
- 规则：新增浏览器持久化只保存算法依据，例如页面/URL 标识、访问次数及少量状态数值；不把整个页面、DOM 或组件状态序列化落盘，不把客户端访问统计放到后端缓存。
- 原因：不同用户客户端资源与访问模式不同，固定 TTL 会同时伤害常用小页面恢复与大量单次 demo 访问的资源控制。
- 适用：本次 Frontstage 生命周期方案重设计与后续缓存策略讨论。用户随后明确“好，就这样按照新方案来”，已批准 W-TinyLFU 近期窗口、频率准入与客户端资源预算方向；允许继续实现和集中验证。固定30分钟主策略不再适用。

## 适用场景

Frontstage TSX 区块源码读取、内容哈希、运行时 Session、Worker 调度、渲染快照缓存、Page/Tab Signal 和页面导航恢复。

## 2026-10-04 16 用户反馈：多区块仍会重画

- 规则：用户反馈多区块报表切回或调整筛选仍明显重画时，不能以源码 304、零新增编译、零新增 native host 挂载和最终高度相同作为体验已修复的充分证据；还需观察内部图表/表格节点、业务请求和过程中的高度变化。
- 原因：外层实例保留不代表子组件或命令式图表资源保留；effect 恢复后清空业务数据可能移除子树，加载态又会触发自动高度重排，最终高度恢复会掩盖中途跳动。
- 适用：Frontstage 多区块页面导航、筛选联动、Activity 恢复、图表生命周期及相关回归。具体根因仍以当次源码和运行态为准。
