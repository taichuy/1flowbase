title: 子 Agent 轨迹以逐次请求为浏览单位
date: 2026-09-22 16
feedback_category: repository
decision_policy: direct_reference
---

规则：用户指出子 Agent 轨迹也应拆成请求，不能仅搬运 Agents → 子工作流 → LLM → Tools 节点树。
原因：旧树即使挪入轨迹仍不能呈现逐次请求，右侧复用整棵节点详情还会重复层级。
适用场景：子 Agent 轨迹与活动分类设计。保留真实节点日志跳转，客户端原始请求与内部 LLM 调用语义应区分；关联必须有后端真实标识，不能凭时间猜测。

2026-09-22 用户已批准修正：子 Agent 分组下按真实内部调用标识列出逐次请求，详情复用事件分类，客户端来源通过真实链接打开；工作流树只在显式查看节点时打开。不能再次用搬运 Agents/Tools 树冒充请求轨迹。

2026-09-22 用户进一步纠正（优先于前述独立请求视图方案）：工作流内部轨迹应是同一事件流；请求事件、工具、轮次/压缩、子任务是事件分类筛选，不能切换到不同列表模型或工作区。沿用现有模型调用事件视图的时间轴、分组、事件行与详情。分页应在后端分类筛选后进行，不能只过滤当前已加载页，也不能靠扫描完全部数据凑匹配项。子任务保留父子关联与来源入口，但不独立呈现另一套请求卡片或节点树。当前独立 AgentRequests 方案需被这一更正取代；此规则取代此前独立子任务工作区。

2026-09-22 用户补充统一内部事件流要求：事件必须显著显示所属节点名称，不能仅显示 node_id；多个 LLM 节点必须易于区分。内部工作流事件还需包含节点自身的执行事件及执行顺序，而不是只记录模型协议调用。方案约束：节点显示名由后端提供并优先采用执行时快照；保留真实节点/运行/调用标识用于关联；时间顺序与因果关系分开，不能将并行执行伪装为串行。执行顺序由真实事件时间和源内序号提供。

2026-09-22 用户纠正统一事件GUI：期望逐条瀑布式事件渐进打开，当前调用分组/节点开始结束行/右侧完整节点卡片重复层级显得拥挤；右侧必须可滚动看到全部内容。后续设计应降低默认层级，节点名称作为事件归属，不以复制整棵节点UI代替事件详情。滚动验收必须实际展开长内容并滚轮到末尾，不能仅截图或验证元素存在。用户已确认：默认平铺，右侧单一滚动内容区，直接打开栏目；完整关系经显式节点日志入口进入并可返回。

2026-09-22 用户进一步收纳要求：右侧节点名/元数据/调用说明等堆叠占用顶部空间，应统一成详情、元数据、节点日志、原文同级Tabs切换，只保留一个来源请求快速跳转链接。保留逐事件浏览和右侧滚动，不能又在Tab内嵌套第二层步骤详情/原文Tabs。

2026-09-22 最新纠正（覆盖上一条Tabs结构）：事件详情使用输入、数据处理、输出、元数据、原文五个同级Tabs，不再包一层详情或内嵌节点日志树。仅呈现选中事件的记录，节点名表示位置，保留来源请求短链接；缺失数据明确未记录，不能借用整个节点最终输入输出。原因：用户只想理解当前事件，重复整套节点工作区增加认知负担。适用于轨迹右侧事件检查器。
