- 规则：已整理收录的项目，榜单优先展示项目库标题和已有整理介绍；没有整理版本时才回退GitHub原文。Star、Fork、增长、名次独立采用本次真实采集数据。
- 原因：只保护项目库文案还不够；若日榜读取当天自动材料title，用户仍会看到英文原始简介，等于展示层没有复用已整理成果。原始材料应保留，不能为修展示而覆盖来源正文。
- 场景：GitHub观察库自动同步后的日榜、项目资料复用与查询优先级验收。后端查询负责取值，前端使用既有字段；验收同时看真实页面及数据保留证据。

- 社区展示纠正（2026-10-18 22）：用户要求社区作为独立类目，展示来源、讨论热度等信息；没有真实排名的社区材料不能沿用官方排名与 Star 增长主视觉。原因：原文序号与缺失增长会误导。适用：社区页面、周期视图及图片导出。后续用户已明确确认拆分，现已完成独立页面与社区图片语义调整；官网和研究文章仅为参考，不应归作社区讨论热度来源。

- 2026-10-18 23 社区概览密度纠正：用户明确要求每项目单行的基础信息表格，字段为仓库名、标题、Star、来源、时间、描述（单行自动省略）。原因：概览用于集中扫读，多段反馈与关注原因导致行高过大；完整分析放详情。适用于社区页面列表，不自行扩展到独立分享图片。已落实42px六列表格。

- 2026-10-18 23 社区表格Star格式：用户要求千位用k缩写，提高扫读密度；>=1000显示一位小数k（113.1k、2.8k），更小值保留整数；悬停保留精确累计数及快照日期。只改展示，不改变事实数据。
