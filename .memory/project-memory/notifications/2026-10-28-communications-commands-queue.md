- 谁在做什么：用户已确认平衡方案并明确要求开始调整，Root 负责实施、隔离装配与集中验收，不重复请求方向批准。
- 目标与动机：相邻入站消息不能各自成为独立 AI 会话或各发一份回答；在尚未回复、AI 正在生成时，后续消息可以追加到同一会话，由 AI 给出覆盖补充内容的完整回答。
- 用户要求：底座提供 /new、/model、/help 等命令；/model 列出可选模型并提供如 /model-user-模型ID 的选择方式。通讯中心渠道配置提供指令表格与开关。
- 来源与边界：指令来源为底座默认、插件声明、用户自定义。自定义绑定工作流明确留到下一步讨论。命令经结构化事件通知触发，不把命令原文直接发给当前绑定 Agent-flow。
- 已确认 /new 语义：旧会话正在生成时停止旧会话，并发送英文提示旧会话已经停止、接下来进入新会话。英文具体措辞尚未作为固定文案确认。
- 沿用既有边界：历史仍按插件 MCP 渐进式查询；本次要求未授权自动回放完整历史或迁移/删除历史记录。
- 已确认平衡范围：持续会话、同轮补充、发送前检查、事件化指令与渠道开关；先支持底座与插件两种来源。模型选择只影响当前聊天对象、后续回答生效，并在 /new 后保留；未知/禁用/参数错误命令明确响应，不送给 Agent-flow。
- 追加边界：生成中补充先持久化，在下一模型调用或安全输入边界消费；复用已完成工具结果，不为追加消息重跑整个工作流。回复提交发送前的补充归当前轮，提交后归同会话下一轮。
- 截止日期：未设；成功标准为连续补充形成完整单次回答、/new 停止旧生成及未发送回复、指令由注册表与事件处理且渠道配置真实生效。
