# 顶部标签新增入口与宽度策略统一

## 时间

`2026-07-11 00`

## 谁在做什么

- 用户要求统一顶部标签新增入口与左侧边栏已完成的“添加菜单”样式和组件。
- 用户指出标签页没有必要过早收缩，因为标签栏右侧仍有大量空白。
- 用户已确认采用方案 B，等待 Standalone Complete Issue 确认后进入前端实现。

## 为什么这样做

- 顶部独立 `+` 图标与左侧新增按钮的视觉语言不一致。
- 当前标签布局在仍有可用空间时提前压缩，降低标签名称可读性和空间利用率。

## 为什么要做

- 让同类新增操作共享组件或稳定的设计变量。
- 让标签优先按内容和可用空间展示，只在容器确实不足时进入收缩、滚动或溢出策略。

## 截止日期

- 无

## 决策背后动机

- 保持现有新建、切换、重命名、移动和删除行为不变。
- 改动限定在前端组件复用和标签栏布局，不扩展到业务 contract 或后端。
- 顶部使用左侧新增按钮的紧凑变体，避免完整侧边栏按钮在顶部造成过重视觉占用。
