# 应用任务报表方向

- 谁在做什么：用户与 Codex 讨论应用 statistics 页面重构，基于 logs 的任务数据；2026-09-22 用户已授权实施，代码已合入本地 dev（42ce3e7db），定向验收通过。
- 已确认：两个分布（模型、用户）与一张通栏趋势；使用者显示用户 name，不按授权账号 / API Key 切换；使用 ECharts。
- 已确认统计边界：只统计主任务，子任务消耗归入主任务，避免父子重复累计。
- 为什么这样做：早期报表设计不完善，用户希望参考所附用量看板，以任务视角理解应用使用情况与消耗。
- 归因已确认：用户按主任务 created_by 聚合并显示 users.name；整棵任务树消耗归入主任务 requested_model_id。时间筛选按主任务开始时间选择任务，子任务跨时间段仍计入所属主任务。主任务耗时不叠加并行子任务。
- 入口联动：模型、用户与时间趋势进入日志时，复用同一主任务时间范围和身份条件；费用未知不当作零。
- 截止日期：未指定。

- 用户纠正（2026-09-22）：首版视觉与参考图差距明显，缺少 Token 缓存命中趋势，卡片区域划分不足。此前技术验收通过不代表用户接受视觉效果；修订必须对照参考图检查独立概览卡、筛选卡、分布卡与通栏 Token 明细/命中率趋势。

- 最新确认（2026-09-22 16）：用户明确两个分布无需并排，改成上下单列，并授权直接调整。已实现独立概览/筛选/分布/趋势卡片；趋势默认输入、输出、缓存读取及右轴缓存命中率。用户分布仍显示 name；无缓存写入字段不虚构 Cache Creation。

- 交互纠正（2026-09-22 16）：时间筛选必须置于概览卡片上方；切换时间/粒度保留旧报表并局部加载，避免整页闪空。原因是整页卸载导致视觉跳动；适用于此应用报表后续交互调整。
