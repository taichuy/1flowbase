# AI Gateway 载荷所有权与临时内存

本文说明请求入口、历史投影、受管供应商 stdio 请求、对象写入和 Agent Flow 回调恢复的内存 owner。协议内容、数据库事实和资源生命周期由原 owner 保持，不以减少功能或限制业务容量换取资源下降。

## 请求入口与冻结输入

Responses 适配器捕获不可变的 `ProviderTransportPayload`，原始 body、canonical digest 和编码长度属于同一个快照。请求翻译借用这个 body，按原顺序完成校验和语义映射；需要 native、preferred 或 compact transport 时，转移捕获的 payload，并在原位置设置 preferred 标记。仅语义映射的分支不保留 transport。Session identity 继续走原独立身份路径；任何确实修改 body 的 continuation / affinity 路径仍须重新计算摘要，不能复用旧快照的 digest。

复用不可变 payload 消除成功保留 transport 分支的第二次整文摘要计算，并避免取出共享 Arc body 时产生的条件性深复制。Arc 引用计数复制本身不等于正文复制。协议字段、未知扩展字段、错误顺序、原始 body 和摘要算法仍由既有 owner 决定。

Run / workflow 输入冻结接收拥有所有权的 JSON Value。对象分支直接移出已有 Map，非对象仍得到空 Map；Run 的 `sys` 也按同一方式移出。环境变量覆盖、recovery 移除、推理默认值、显式覆盖、workflow trigger 与错误传播的顺序保持原样。设根对象的深复制量为 B、sys 的独立深复制量为 S，Run 删除 B+S 的复制工作，workflow 删除 B 的复制工作；后续必要的读取、编码、数据库写入与独立可变副本仍有各自成本。

## 历史投影与数据库读取

长期历史的事实仍在数据库中，原生投影进度只保存 revision、游标、数量与冲突键等索引信息。完整初始化和显式修复需要恢复既有事实；当前实现逐条读取 context / event，但按 canonical key 归并的唯一事实仍由本次事务持有。流式读取减少同时持有的原始行，不意味着整次重建变成常量内存。当前请求完整 prompt 的处理成本与历史唯一事实的成本应分别度量，不能只用消息条数代替编码字节数和对象结构。

数据库持久化、存活堆对象与进程 RSS 是三种不同观测。请求和返回值释放后，连接缓冲或分配器仍可能保留容量；连接池关闭后的下降不能单独证明某一类缓冲的归因。隔离资源验证应分别记录实际入口、返回值保留、正文释放、同一物理连接重取、显式 `shrink_buffers` 与池关闭，并用不执行 shrink 的对照及固定历史、固定正文重复运行区分连接保留容量与累积增长。这些动作仅用于隔离测试，不引入每请求收缩、历史截断、业务容量上限或长期 ephemeral 正文缓存。

## 供应商请求

令 S 为当前 serde_json 编码，P 为其默认解析，N=P∘S。类型化请求经过原 host capability 投影 H 后，仍将 N(N(H(request))) 交给原 MultiplexEnvelope 编码；直接 JSON 请求仍使用 N(request)。

N 对所有 JSON Value 并非恒等：浮点解析可能改变最后几位，解析也有递归深度边界。因此不能把编码/解析往返直接替换为传递原 Value。保留原方法、观测 marker、字段顺序、错误分类和以下顺序：

    serialize → 原字节预算 acquire → parse → enqueue → actor encode

仅缩短不可再观察的临时对象生命周期：类型化入口的字节缓冲在调用 await 前释放；JSON 入口在编码后释放输入 Value，在预算取得和解析成功后释放字节缓冲。预算仍按原编码长度加 envelope 余量计算，失败、取消和 lease owner 不变。

设输入占用 P 字节、两次编码缓冲容量为 S1/S2。原长等待可能保留 P+S1+S2 的临时数据；释放后这些对象不跨响应等待。瞬时转换仍需原有缓冲，CPU 和最坏空间阶数仍为 O(P)，并不代表所有分配或解析都被消除。并发收益取决于各请求所在阶段，峰值 RSS 由同负载测量结算。

## 对象写入

FileStoragePutInput 拥有 Vec<u8>。上传服务在转移前记录长度；调试/轨迹正文投影移动已经生成的完整字节。Local 把 Vec 直接交给 Tokio 写入，RustFS 直接转换为 SDK Body。驱动保持原配置校验、路径、MIME、写入顺序与错误映射。

这删除一个原先发生在驱动边界的整文件副本。每个大小 B 的对象少一次 O(B) 分配/复制；写入本身仍为 O(B)，输入缓冲仍为 O(B)。N 个同时进入该阶段的上传，缓冲本体最多减少约 N×B，Local 与 RustFS 是替代驱动，不把它们的收益相加。multipart 收集、网络和操作系统缓冲不在此项变更范围。

文件和 sidecar 的字节内容、数据库元数据以及鉴权均不变化；没有新增数据库记录、跨请求缓存或临时落盘。流式上传是独立 contract，需要处理字段顺序、长度和取消清理，不由此次所有权调整隐式引入。

## 回调等待快照

可见内部工具恢复返回拥有所有权的 Waiting 状态时，移动其 checkpoint_variable_pool；随后仍复制一次，使执行结果和持久化 checkpoint 拥有独立可变的值。原始输入 checkpoint 的保护性复制保留。

设此分支的变量池大小为 P，进入该分支 C 次。中间池完整复制从每次两份降为一份，删除一份 O(P) 复制；总时间/空间的阶数保持不变。峰值由同时进行的恢复数量决定，不能用累计 C 直接推算同时驻留内存。

## 验证边界

协议/错误等价、文件字节与 metadata、回调快照独立性分别由所属生产测试覆盖。有限模型、反例检测和源码绑定片段 probe 解释局部变换；完整 API 行为和混合负载资源由独立的同版本运行证据覆盖，局部计时不替代服务吞吐或容量结论。
