# 通讯中心

[English](README.en.md)

通讯中心管理渠道、用户会话、收到的文件和收发状态。站内通知仍使用原收件箱；渠道管理入口为 `/settings/communications`。

## 配置和消息

接收型插件声明独立的接收、发送贡献，以及内置提示词和 MCP 工具。创建渠道时，宿主注册一个渠道专属 MCP 实例。绑定 Agent-flow 时默认选择该实例，并可选择更多实例。模型和推理强度选项复用 AI 助手的应用能力规则；文件表留空沿用文件管理的默认表。

通讯运行以稳定的应用与插件系统提示词、独立的底座会话信息、当前用户消息三个逻辑消息开始。插件提示词可编辑。历史不自动回放；模型按现有 MCP 渐进式发现、查看和调用机制查询历史与文件。供应商可使用自己的 system 表达形式；稳定前缀有利于缓存，但不保证命中。

## 接收与恢复

插件返回消息批次和候选游标。宿主在一个事务中去重并保存消息、加密文件下载引用、授权状态与游标；失败不推进游标。接收、发送和授权维护不能独立抢读同一个供应商游标。

外部聊天的历史 conversation、AI session、回复 turn 和工作流 run 分别持有身份。同一外部聊天复用 AI session；一轮回复可以包含多条入站消息，每条原始消息仍单独保留。不同聊天可以独立执行。附件通过有界插件传输块下载，上传现有文件管理后保存文件表和记录引用。失败状态保留，是否可以重试由后端返回。已开始但无法确认结果的发送标记 unknown，不自动重发。

模型只收到文件的安全引用；供应商下载 token、加密密钥和受管账号凭证不进入页面、提示词或 MCP 结果。

## 排队和追加

普通消息先持久化，再按聊天内的接收顺序加入当前回复轮次。模型生成中收到的补充，在模型调用前、完整工具结果后或最终候选回答后消费。最终发送预留与新输入使用同一聊天锁排序：预留前的补充必须纳入当前轮次，预留后的消息进入下一轮。

追加保留模型 transcript 和已完成工具结果；不重新分派整个工作流，不重放已完成的副作用节点。人工确认或外部工具回调恢复后继续使用同一轮次、claim 和待完成的模型节点。最终 Answer 必须能从保留的模型输出经纯投影重新计算；若 Answer 依赖不可安全重算的已完成节点，追加明确失败，不静默丢弃补充或重复执行外部动作。

输入消费位置和继续执行状态原子保存。重启可接回尚未开始的运行和已有等待点；无法确认执行结果的运行不会自动从头执行。已有历史、渠道、授权和供应商游标保持原有身份。

## 快捷指令

渠道绑定配置中的指令表展示指令、来源、说明、开关和不可用原因。底座指令默认开启：

| 指令 | 行为 |
| --- | --- |
| `/new` | 停止旧会话生成，作废未发送的旧回复并开启新 AI session |
| `/model` | 列出绑定应用允许选择的模型 |
| `/model-user-<模型 ID>` 或 `/model <模型 ID>` | 选择当前外部聊天后续轮次的模型 |
| `/help` | 列出当前渠道已启用且可用的指令 |

`/new` 经独立控制通道处理。宿主先持久化旧 session 失效，再取消并等待旧执行退出，随后回复 `The previous conversation has stopped generating. A new conversation has started.`。已经完成的外部动作和已经提交供应商的消息不能撤回。聊天模型选择在 `/new` 后保留，不改变渠道默认模型或正在执行的轮次。

取消按单次运行时请求传播，成功提示需要等待该请求及其宿主资源清理结束。共享串行驱动若没有单次调用取消协议，宿主等待调用结束或明确报告取消失败，不通过终止共享进程中断其他会话。

未知、禁用、不可用和参数无效的指令都有明确回复，原文不会进入绑定 Agent-flow。命令原始消息仍保留在历史中。自定义工作流指令尚未开放。

插件通过全局 `PluginManifestV1.communication_commands` 声明指令，与接收或发送能力独立。每个声明绑定一个 `1flowbase.communication.command.requested` 事件订阅贡献；指令 ID 使用 `publisher/plugin/local`。底座保留 `new`、`model`、`help` 和 `model-user-*` 名称。

命令先提交持久化结构化事件，冻结唯一处理目标及授权版本；插件停用、卸载或权限撤销后不能继续执行。插件返回 `CommunicationCommandReply { text }`，回复目的地由宿主从入站记录解析。命令效果、回复收据和供应商投递分别记录，处理 ACK 不等于消息已送达。事件重投复用同一结果收据；这不承诺任意插件外部副作用的跨系统 exactly-once。

## MCP 与回复

MCP 工具来自插件声明并落为真实实例、工具和绑定，继续使用统一的发现策略。宿主给通讯调用绑定工作区、渠道和外部身份范围；模型参数只能选择范围内的会话或文件，不能扩大权限。

回复目标来自持久化的入站发送者与会话，不能被后续消息改写。执行成功后复用业务会话最终回答投影，只发送最终正文；推理、工具输出、等待回调、失败和超时占位均不作为用户答复。

## 验证边界

接收与历史基础能力的验收归属见 [Root #2670](https://github.com/taichuy/1flowbase/issues/2670)，持续会话、追加和指令见 [Root #2695](https://github.com/taichuy/1flowbase/issues/2695)。协议 mock、真实数据库和微信实网收发分别记录；模拟成功不能证明微信实际收到消息。
