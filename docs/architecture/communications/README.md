# 通讯中心

[English](README.en.md)

通讯中心管理渠道、用户会话、收到的文件和收发状态。站内通知仍使用原收件箱；渠道管理入口为 `/settings/communications`。

## 配置和消息

接收型插件声明独立的接收、发送贡献，以及内置提示词和 MCP 工具。创建渠道时，宿主注册一个渠道专属 MCP 实例。绑定 Agent-flow 时默认选择该实例，并可选择更多实例。模型和推理强度选项复用 AI 助手的应用能力规则；文件表留空沿用文件管理的默认表。

通讯运行以稳定的应用与插件系统提示词、独立的底座会话信息、当前用户消息三个逻辑消息开始。插件提示词可编辑。历史不自动回放；模型按现有 MCP 渐进式发现、查看和调用机制查询历史与文件。供应商可使用自己的 system 表达形式；稳定前缀有利于缓存，但不保证命中。

## 接收与恢复

插件返回消息批次和候选游标。宿主在一个事务中去重并保存消息、加密文件下载引用、授权状态与游标；失败不推进游标。接收、发送和授权维护不能独立抢读同一个供应商游标。

会话消息按顺序领取并持有可续租的处理 claim。附件通过有界插件传输块下载，上传现有文件管理后保存文件表和记录引用。失败状态保留，是否可以重试由后端返回。已开始但无法确认结果的发送标记 unknown，不自动重发。

模型只收到文件的安全引用；供应商下载 token、加密密钥和受管账号凭证不进入页面、提示词或 MCP 结果。

## MCP 与回复

MCP 工具来自插件声明并落为真实实例、工具和绑定，继续使用统一的发现策略。宿主给通讯调用绑定工作区、渠道和外部身份范围；模型参数只能选择范围内的会话或文件，不能扩大权限。

回复目标来自持久化的入站发送者与会话，不能被后续消息改写。执行成功后复用业务会话最终回答投影，只发送最终正文；推理、工具输出、等待回调、失败和超时占位均不作为用户答复。

## 验证边界

验收计划与证据归属见 [Root #2670](https://github.com/taichuy/1flowbase/issues/2670)。协议 mock、真实数据库和微信实网收发分别记录；模拟成功不能证明微信实际收到消息。
