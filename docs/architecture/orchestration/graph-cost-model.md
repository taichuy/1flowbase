# 工作流图成本与等价性规范

工作流节点数量不是并发数，也不是服务容量上限。编译、执行、外部调用与持久化各自拥有成本；评估时保留图形状、实际路径和数据大小。

## 成本模型

令 `V` 为节点数，`E` 为原始边数（包含平行边），`K` 为一次执行段中的激活次数，`Q` 为变量可达性查询数，`P_i` 为第 i 次暂停/恢复时的变量池大小，`B_j` 为第 j 个实际执行节点的输入、输出和观察数据字节数。

| 路径 | 成本及含义 |
| --- | --- |
| 出边定位 | 全边扫描需要 `K×E` 次 source 判断。调用内借用索引构造访问 E 条边，随后访问 `Σ outdegree(v_j)` 条相关边；`BTreeMap` 构造/查询另有 `O((E+K) log(V+1))` 比较成本。激活目标的 `BTreeSet` 成本两种实现相同。 |
| 可达性校验 | 每个查询保留原 DFS，最坏为 `O((V+E) log(V+1))`；Q 个查询仍可能重复追溯。visited 使用 `&str`，不为每次访问复制节点 ID，空间仍为 O(V)，不建立全图传递闭包。 |
| 节点业务执行 | 主调度按拓扑顺序等待节点；外部模型、HTTP、数据库与工具调用的耗时由实际路径决定。内部工具的 panel 有独立调度语义，不能把 V 当作同时执行 V 个外部调用。 |
| 运行内存 | 包括计划、变量池、节点 trace、生命周期记录及执行上下文；除结构开销外随 `Σ B_j` 增长。完整变量池复制主要位于等待/恢复及内部工具隔离边界，复制量与 `Σ P_i` 相关，普通直通链不存在每个节点都复制整池的步骤。 |
| 持久化 | `PersistedNodeLifecycle` 为实际执行节点创建/完成运行记录，并投影开始/完成事件；流事件还由持久化 owner 处理。记录操作随 K 增长，额外 token/tool 事件另计，不能把领域 repository 调用次数直接写成 SQL 往返次数。 |

总耗时需拆成图校验、调度、节点业务、持久化与恢复成本。纯算法探针不代表 HTTP P95 或数据库吞吐。并发 R 个同形运行时，请求私有内存按 R 放大；实际容量还取决于输出大小、外部延迟、到达率与运行宿主。

## 出边投影与激活

对有序边序列 `E`，规范为：

```text
I(u) = [e ∈ E | e.source = u]                    // 保留顺序与重复项
T = [e.target | e ∈ I(u) ∧ eligible(node,h,e)]
A' = A ∪ set(T)
handled = (T ≠ [])                              // 不是 A' ≠ A
```

`if_else` 只匹配所选 handle；其他节点显式选择 handle 时精确匹配，默认路径排除 error 与内部工具连接边。原始边为空时，T 使用节点的 `downstream_node_ids`。错误目标已激活也必须返回 handled=true。

索引构造的循环不变量为：处理任意前缀 P 后，每个 source 对应的列表恰好等于 `filter(P, source)`。空前缀成立；追加边 e 时，仅 `e.source` 的列表末尾追加 e，其他列表不变。因此不变量对任意有限边序列成立。对相同有序投影执行同一个 eligibility/union fold，激活结果与存在性相同。

`CompiledEdgeIndex` 是借用不可变边切片的调用内视图，不写入 `CompiledPlan` 的序列化表示。编译器的工具分支检查和执行器复用同一实现。主执行段与内部工具分支各自建立视图，panel 复用所在分支的视图；单次公共激活入口保持直接扫描，避免为孤立查询建立索引。

## 借用可达性

`node_depends_on(u,v)` 表示存在至少一条边的依赖路径；不默认令 `u` 可达自身。保持原栈顺序、命中提前返回、缺失节点与防环行为。

删除 `current.to_string()` 后，旧 visited 集合的字符串值与新 visited 集合引用的字符串值一一对应。Rust 字符串借用的比较按内容，节点集合在查询期间不可修改；因此每一步 insert 的布尔结果相同，后续分支和栈转移相同。借用检查器保证引用有效，字符串比较和 `BTreeSet` 的标准库契约是这项推理的前提。

## 机器检查的层次

1. 数学归纳推导投影前缀不变量与逐目标集合转移，推导对象是上述数学模型，前提是标准容器的查找/追加/比较契约。这一模型推导与下面实际执行的机器检查分开记录。
2. Rust 领域验证直接调用生产 `CompiledEdgeIndex` 和激活函数：穷举两个节点、六类 handle、长度 0～3 的全部有序边序列、节点类别、已有 active 集合与空边 fallback，检查 1,385,088 个激活状态和 43,275 个有序投影。
3. 对 0～4 节点的全部有向图，用独立 Floyd–Warshall 非自反传递闭包比较生产 DFS，包含环、自环与缺失节点，共 1,646,745 次查询。
4. 真实执行入口检查 750/1400 节点链的每项输出、终态、trace 顺序；分支、错误策略、工具 panel、暂停恢复由既有执行器回归覆盖。显式 ignored profile 用例用于量化，不给普通门禁添加时间阈值。

有限域检查不等于任意 Rust 程序的无界形式化证明，也不覆盖外部 provider、数据库事务或网络故障。归纳模型、有限域实现精化、集成行为、资源测量分别保留证据和源码版本。受控错误必须被 verifier 识别，不能仅依据进程退出成功认定检查有效。
