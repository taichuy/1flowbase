# PostgreSQL 树存储

`parent_id` 是父子关系真值，`sibling_rank` 定义同级顺序。底座在物理表维护不可编辑的 `tree_path ltree` 派生列；路径由无连字符 UUID 标签组成，名称和排序变化不改变路径。该列不是公开模型业务字段，不允许用户声明同名字段。

适用范围为 `core/ordered_tree/v1` 的主数据源动态表、`departments` 与 `frontstage_block_nodes`。独立的 `frontstage_pages` 父子结构不属于此模板。

## 部署与迁移

使用 PostgreSQL 自带的 contrib 扩展 `ltree`（当前 PG18 环境提供1.3），不增加 Node/Rust 包。正式 migration 安装到 `public`，安装账号需具备该扩展的创建权限，后续查询连接须能解析公共扩展运算符。扩展不是临时缓存，不随隔离测试 schema 删除。

新增 migration 对历史树回填，遇到路径字段冲突、环或无法到达的节点会整体失败，不自动重挂用户数据。新模型通过同一底座安装函数建立路径和 GiST 表达式索引。上线前应备份并在代表性数据副本确认回填时长；回填DDL需要表锁。

## 写入与读取

结构命令沿用模型/作用域/树分区事务锁。数据库触发器从父节点路径生成新路径；换父后在同一事务重写全部后代路径，回滚也回滚路径。不允许直接篡改路径或身份/分区。叶删除、子树删除及防环规则保留。

后代匹配使用 `ARRAY[tree_path] <@ root.tree_path`，与单一路径的后代语义相同；索引采用 `gist__ltree_ops`，仅保存签名并由 PostgreSQL 回表复核，避免普通 `gist_ltree_ops` 保存完整深路径导致索引页大小限制。祖先匹配使用路径关系或父链，必须同时过滤 `scope_id` 和 `tree_partition_id`；路径和索引不承担授权。GiST使用官方默认配置，不根据开发机容量设置业务限制。排序仍以 `sibling_rank` 为准，不把UUID路径字典序当作业务排序。

组织成员查询在数据库中筛选子树并去重，角色和部门归属批量读取。系统根浏览入口包含未分配部门的用户，不创建隐含部门归属，不改变直接部门角色授权语义。

## 验证与回退

隔离CI验证正式migration的旧数据回填、创建/移动/删除/回滚、作用域隔离和并发防环，并记录路径查询执行计划。性能结论须同时观察读取和移动写放大，不能仅凭新增索引推断。索引有损签名可能产生候选误命中，但数据库复核保证结果准确；深度增加可能降低签名筛选效率，不增加业务深度上限。

代码回退时保留扩展、列和维护触发器，不删除用户数据；旧代码若不能在保留触发器条件下通过原有树行为验证，应前滚修复。扩展或列的卸载属于单独的数据迁移。

官方依据：[ltree 文档](https://www.postgresql.org/docs/18/ltree.html)，本地同源实现 `postgres/contrib/ltree/_ltree_gist.c`。

## 分页契约

`tree/roots`、`tree/children/{id}`、`tree/descendants/{id}`、`tree/search` 返回 `{items, has_more, next_cursor}`，不再返回裸数组。调用方把 `next_cursor` 原样传入下一次相同查询的 `cursor`；`has_more=false` 时 `next_cursor=null`。模板描述符、OpenAPI 和 TypeScript SDK 同步消费此契约，升级时须同步调用方。`tree/ancestors/{id}` 保持从根到直接父节点的数组。

`limit` 是正整数页大小（默认100，搜索默认20），不是节点容量上限；不再限制1000条或100个搜索命中。`max_depth` 是可选正整数过滤条件，省略时不限查询深度，仍按页返回；不再默认截断32层或限制256层。底层整数类型和 PostgreSQL ltree 自身的表达能力仍有物理边界。搜索分页数量按命中节点计算，`items` 还包含这些命中的祖先上下文；上下文可能跨页重复，客户端按ID合并并保留 `is_match=true`。

分页采用 keyset，节点同级顺序为 `sibling_rank COLLATE "C", id`，后代保持祖先同级顺序组成的深度优先顺序。游标包含查询上下文、锚点ID和固定大小的路径/顺序摘要，不携带整条深路径。游标绑定模型、作用域、分区、查询种类和过滤条件；它不是授权凭证。锚点校验与页面查询在同一只读 repeatable-read 事务中执行。不同查询使用游标返回400；锚点删除、换父、相关顺序变化导致摘要不匹配时返回409 `tree_stale_cursor`，调用方丢弃游标重新加载。

跨请求采用实时视图，不维护长期快照。静态数据完整遍历不重不漏；其他节点在已读边界前插入或跨边界移动，可能导致本轮遍历漏读或重复，重新加载可取得当前视图。需要一致性导出应采用单独的快照/导出能力，不能把实时分页视作快照。分页限制响应规模，但后代排序和搜索上下文仍有数据库计算成本；性能以执行计划和实际负载证据为准。

组织专用 `GET /api/console/settings/departments` 使用同一分页封装：缺省读顶层，`parent_id` 读直接子部门，`prefix` 搜索并返回祖先上下文，`ids`（逗号分隔UUID）补查已有选择，后三种条件不能混用。每项保留部门字段、角色和子树去重人数，并增加 `has_children`、`is_match`。选中ID补查按不可变ID排序，因此仅调整部门位置不会使其游标失效。成员筛选直接在后端匹配子树，不依赖前端是否展开。组织页面按展开和续页加载；保存后使用定向读取返回部门，不扫描全表。

运行保护沿用统一接口内核的截止时间、取消和部署治理；本模板不建立独立的容量猜测、超时或缓存机制。失败明确返回错误，不以部分结果冒充完整读取。前台块树当前既有外部数组接口保持原有语义，仅适配内部共享分页查询；本次不将其声明为可游标遍历的接口。
