# PostgreSQL 树存储

`parent_id` 是父子关系真值，`sibling_rank` 定义同级顺序。底座在物理表维护不可编辑的 `tree_path ltree` 派生列；路径由无连字符 UUID 标签组成，名称和排序变化不改变路径。该列不是公开模型业务字段，不允许用户声明同名字段。

适用范围为 `core/ordered_tree/v1` 的主数据源动态表、`departments` 与 `frontstage_block_nodes`。独立的 `frontstage_pages` 父子结构不属于此模板。

## 部署与迁移

使用 PostgreSQL 自带的 contrib 扩展 `ltree`（当前 PG18 环境提供1.3），不增加 Node/Rust 包。正式 migration 安装到 `public`，安装账号需具备该扩展的创建权限，后续查询连接须能解析公共扩展运算符。扩展不是临时缓存，不随隔离测试 schema 删除。

新增 migration 对历史树回填，遇到路径字段冲突、环或无法到达的节点会整体失败，不自动重挂用户数据。新模型通过同一底座安装函数建立路径和 GiST 表达式索引。上线前应备份并在代表性数据副本确认回填时长；回填DDL需要表锁。

## 写入与读取

结构命令沿用模型/作用域/树分区事务锁。数据库触发器从父节点路径生成新路径；换父后在同一事务重写全部后代路径，回滚也回滚路径。不允许直接篡改路径或身份/分区。叶删除、子树删除及防环规则保留。

后代匹配使用 `ARRAY[tree_path] <@ root.tree_path`，与单一路径的后代语义相同；索引采用 `gist__ltree_ops`，仅保存签名并由 PostgreSQL 回表复核，避免普通 `gist_ltree_ops` 保存完整深路径导致索引页大小限制。祖先匹配使用路径关系或父链，必须同时过滤 `scope_id` 和 `tree_partition_id`；路径和索引不承担授权。GiST使用官方默认配置，不根据开发机容量设置业务限制。排序仍以 `sibling_rank` 为准，不把UUID路径字典序当作业务排序。

组织成员查询在数据库中筛选子树并去重，角色和部门归属批量读取。系统根浏览入口包含未分配部门的用户，不创建隐含部门归属，不改变直接部门角色授权语义。

## 验证与回退

隔离CI验证正式migration的旧数据回填、创建/移动/删除/回滚、作用域隔离和并发防环，并记录路径查询执行计划。性能结论须同时观察读取和移动写放大，不能仅凭新增索引推断。索引有损签名可能产生候选误命中，但数据库复核保证结果准确；深度增加可能降低签名筛选效率，不增加业务深度上限。

代码回退时保留扩展、列和维护触发器，不删除用户数据；旧代码若不能在保留触发器条件下通过原有树行为验证，应前滚修复。扩展或列的卸载属于单独的数据迁移。

官方依据：[ltree 文档](https://www.postgresql.org/docs/18/ltree.html)，本地同源实现 `postgres/contrib/ltree/_ltree_gist.c`。
